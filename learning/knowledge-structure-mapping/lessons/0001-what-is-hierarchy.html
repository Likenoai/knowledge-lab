Knowledge Structure Mapping · Lesson 0001

什么叫“层级”？

第一课只解决一个问题：“画成上下两层”为什么不等于“存在层级关系”？

1. 先拆掉一个直觉

下面四组内容都可以被画成“上—下”，但它们的语义关系并不相同。

动物 └─ 猫 汽车 └─ 发动机 周一 └─ 周二 注意力 └─ 悬念
猫 → 动物IS_A / SUBCLASS_OF
猫是一种动物
发动机 → 汽车PART_OF
发动机是汽车的一部分
周一 → 周二PRECEDES
周一先于周二
注意力 ↔ 悬念可能是关联或机制关系，不能仅凭排版判定父子
第一原则
层级不是一种排版形状。层级必须由某一种明确的 ordering relation（排序 / 上下位关系）产生。

2. 更精确的表示

任何知识结构至少可以先拆成：

Nodes（节点） + Relations（关系）

例如：

Nodes = {猫, 动物} Relation = IS_A 猫 --IS_A--> 动物

只有在知道“边是什么关系”之后，才有资格问：这是不是 hierarchy（层级）？

工作定义：Hierarchy（层级）= 一组节点被某种一致的上下位 / 排序关系组织起来。后续学习 Order Theory（序理论）时，会进一步形式化到 Partial Order（偏序）等结构。

3. “父节点”不是一个关系名称

日常表达真正需要追问
A 是 B 的父节点为什么？边的 Relation Type（关系类型）是什么？
A 在 B 上面这是 IS_A、PART_OF、PRECEDES，还是仅仅为了排版？
A 和 B 同级它们是否由同一个 Criterion（划分标准）得到？

4. 第一课的核心判断式

不要先问： “谁在上，谁在下？” 先问： “A 和 B 之间是什么关系？” 然后再问： “这种关系是否产生一个层级？”

5. 最小练习

① 金毛犬 → 狗
你认为是什么关系？
② 车轮 → 汽车
你认为是什么关系？
③ Advantage（优势） → Relative Effect（相对效应）
它更像“子类”，还是“一个维度的取值”？
④ Suspense（悬念） → Attention（注意力）
仅凭这两个概念，你能宣布它们是父子关系吗？为什么？

6. 本课只需要带走一句话

Hierarchy is relation-dependent.
层级依赖关系类型；没有先定义关系，就没有资格谈“父子层级”。
