# Premise Architecture（故事前提架构）

分析一个题材/设定给“主角—世界关系”加入了哪些基础条件。

先读取 [../../research/00_短剧题材研究_层级地图.md](../../research/00_短剧题材研究_层级地图.md)。该文件是当前分类的单一来源。

## Scope（边界）

当前只分析 Premise（故事前提）层。

把以下内容留给其他层：

- Audience-side Value（观众侧价值）；
- Goal / Action（目标 / 行动）；
- Plot Causality（剧情因果）；
- Story Progression（故事推进）。

只有用户明确要求时才跨层。

## Process（执行流程）

◆ **Normalize（规范化）**

先用一句话写清设定，不把后续剧情结果写进定义。

◆ **Classify（多标签分类）**

检查设定是否改变以下基础条件：

- Advantage Architecture（优势架构）
- Constraint / Disadvantage Architecture（约束 / 劣势架构）
- Trade-off Architecture（交换 / 代价架构）
- Transformation Architecture（状态转换架构）
- World-Rule Architecture（世界规则架构）
- Epistemic Architecture（信息 / 认知架构）
- Problem / Threat Architecture（问题 / 威胁架构）
- Relationship Architecture（关系架构）

这些是可重叠维度，不是互斥题材标签。

◆ **Explain the delta（解释变化量）**

对每个命中的架构回答：

- 原始条件是什么？
- 设定改变了什么？
- 改变发生在主角、世界、信息、关系还是问题状态？
- 这是正向不对称、负向不对称、交换，还是状态/规则变化？

◆ **Delegate Advantage（分派优势分析）**

若命中 Advantage Architecture（优势架构），Call the Skill tool with "advantage-architecture"。

◆ **Guard the layer（守住层级）**

如果分析开始进入“角色怎样利用优势”“如何推动剧情”“怎样形成爽点”，明确标记这些属于后续层，不在本次 Premise 诊断中展开。

## Completion criterion（完成标准）

完成时必须做到：

- 所有重要设定效果都落到至少一个基础前提机制；
- 重叠关系被显式标出；
- 没有把市场题材标签当成底层机制；
- 没有把 Payoff（收益）误写成 Advantage（优势）；
- 当前分类中的工作假设与已验证知识不混写。

## Output（输出）

优先使用结构树：

~~~
题材 / 设定
├─ Premise Function A（前提功能A）
│  └─ 改变了什么
├─ Premise Function B（前提功能B）
│  └─ 改变了什么
└─ 当前边界 / 未展开层
~~~
