# Knowledge Structure Mapping｜结构关系词表与判定规则

> 状态：v0.1 Working Reference（工作参考）
> 用途：未来 `knowledge-structure-mapping` Skill 的支持材料。
> 核心原则：先判 relation type（关系类型），再决定是否建立 hierarchy（层级）。

## 1. 核心 Node Type（节点类型）

| Node Type | 含义 | 示例 |
|---|---|---|
| Instance（实例） | 一个具体对象 / 个案 | 某一部具体作品 |
| Class / Concept（类 / 概念） | 一组对象或抽象概念 | 重生题材、优势 |
| Dimension / Facet（维度 / 分面） | 描述对象的一个轴 | Advantage Type、Cost |
| Value（取值） | 某维度上的具体值 | Information Advantage |
| Component（组成部分） | 整体中的部分 | 某框架中的模块 |
| Process / Stage（过程 / 阶段） | 时间或执行链中的节点 | Research → Synthesis |
| Relation（关系） | 连接节点的谓词 | causes、part-of |

如果 Node Type 不清楚，先标记 unknown，不急于建父子关系。

## 2. 优先 Relation Type（关系类型）

### ◆ INSTANCE_OF（实例属于类）

形式直觉：`x ∈ A`。

测试：x 是 A 的一个具体实例吗？

例：`某作品 INSTANCE_OF 重生短剧`。

不要和 IS_A 混用。

### ◆ IS_A / SUBCLASS_OF（是一种 / 子类）

形式直觉：`A ⊆ B`。

必要测试：任何 A，在定义上是否都应该是 B？

例：`Information Advantage IS_A Advantage`。

警告：当前恰好 A 的实例都落入 B，不足以单独证明 IS_A。

### ◆ PART_OF（部分—整体）

测试：A 是构成 B 的一部分，而不是一种 B 吗？

例：`某分析模块 PART_OF 某完整工作流`。

### ◆ FACET_OF / DIMENSION_OF（分面 / 维度）

测试：A 是描述 B 的一个独立观察轴吗？

例：
`Relative Effect FACET_OF Premise Architecture`
`Locus FACET_OF Premise Architecture`

不同 facet 的 values 不能直接作为同一组 siblings。

### ◆ VALUE_OF（维度取值）

例：
`Advantage VALUE_OF Relative Effect`
`Relationship VALUE_OF Locus`

### ◆ BROADER / NARROWER（更广 / 更窄）

用于概念广狭关系。当存在语义层级，但不准备做严格 subclass 声明时，可优先使用 SKOS 风格的 broader / narrower。

### ◆ ASSOCIATED_WITH（关联）

用于稳定语义关联，但不存在上下位关系。

例：`Suspense ASSOCIATED_WITH Curiosity`。

### ◆ PRECEDES（先于）

只表示顺序。不要因为 A 在 B 前面，就说 A 是 B 的父节点。

例：`Premise Analysis PRECEDES Plot Analysis`。

### ◆ CAUSES / ENABLES / CONSTRAINS（导致 / 使能 / 约束）

这些是机制关系，不是 taxonomy relation。

例：`Information Asymmetry ENABLES Dramatic Irony`。

因果关系需要相应证据等级，不能只为了画图方便而声明。

### ◆ EQUIVALENT_TO / SAME_AS（等价 / 同一）

仅在真正等价时使用。“高度相似”“当前外延相同”“经常一起出现”均不足以推出等价。

## 3. Sibling Check（同级检查）

在输出以下结构前：

```text
Parent
├─ A
├─ B
└─ C
```

强制检查：

◆ Criterion（划分标准）：A/B/C 是否回答同一个分类问题？

◆ Node Type（节点类型）：A/B/C 是否是同一类型的节点？

◆ Relation Type（边类型）：A/B/C 与 Parent 的关系是否相同？

◆ Overlap（重叠）：是否允许交叉归属？

◆ Exhaustiveness（穷尽）：是否声称这是完整分类？如果不是，不要暗示“只有 A/B/C”。

## 4. Tree / DAG / Facet / Graph 决策

### Tree（树）

仅当：关系主要是一种 hierarchy；每个节点只有一个直接父节点；多维交叉很少。

### DAG（有向无环图）

当：仍然是同一种 hierarchy relation，但允许 multiple inheritance（多重上位）。

### Faceted Model（分面模型）

当：同一对象必须同时从多个独立轴描述，例如 Locus / Operation / Relative Effect。

### Labeled Graph（带标签关系图）

当：is-a、part-of、causal、sequence、association 等多种关系同时存在。

## 5. Current Node（当前节点）定位模板

```text
Current Node：
Node Type：
Relation to Parent：
Parent：
Siblings under same criterion：
Children / narrower concepts：
Orthogonal facets：
Upstream prerequisites：
Downstream consequences：
Unresolved relation conflicts：
```

注意：上游 / 下游不等于父 / 子。

## 6. 最小输出协议

未来 Skill 默认先输出：

```text
① Nodes（节点）
② Relation Types（关系类型）
③ Same-axis Groups（同轴并列组）
④ Hierarchy / Facets / Graph（结构表示）
⑤ Current Node（当前节点）
⑥ Conflicts / Unknowns（冲突 / 未确定）
```

不要一上来画树。

## 7. 项目中的直接示例

旧结构：

```text
Premise Architecture
├─ Advantage
├─ Constraint
├─ Trade-off
├─ Transformation
├─ Relationship
└─ World-Rule
```

问题：

```text
Advantage / Constraint / Trade-off
= Relative Effect（相对效应）的值

Transformation
= Operation（变化方式）的值

Relationship / World-Rule
= Locus（改变落点）的值
```

更合理：

```text
Premise Architecture
│
├─ FACET_OF → Locus（改变落点）
│   ├─ Character
│   ├─ Relationship
│   ├─ Information
│   └─ World / Rule
│
├─ FACET_OF → Operation（变化方式）
│   ├─ Add
│   ├─ Remove
│   └─ Transform
│
└─ FACET_OF → Relative Effect（相对效应）
    ├─ Advantage
    ├─ Disadvantage
    └─ Trade-off
```

关键提升不是“树更漂亮”，而是先发现原来的 sibling relation 根本不成立。
