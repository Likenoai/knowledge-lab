Knowledge Structure Mapping · Partial Order

Partial Order（偏序）：层级的数学骨架

这一课解释：为什么 hierarchy（层级）不等于一条线、不等于一棵树，也不要求所有节点都能互相比较。

1. 先限定：偏序只讨论“同一种关系”

不能把 IS_A、PART_OF、CAUSES 混在一起后问它们是否构成一个偏序。

先固定 Relation Type ↓ 再检查这一个 relation 是否形成 order

在知识层级中，最典型的是对同一种 subsumption / broader-than relation 做偏序分析。

2. Partial Order 的三个性质

Reflexive（自反）

每个元素都与自身满足该关系。

A ≤ A

在可视化中通常不会画这条自环。

Antisymmetric（反对称）

如果 A ≤ B 且 B ≤ A，那么 A 与 B 应视为同一位置 / 同一元素。

A ≤ B B ≤ A ⇒ A = B

如果两个不同概念互相都是对方的上位，通常说明存在建模冲突或实际上应处理为等价。

Transitive（传递）

如果 A ≤ B 且 B ≤ C，那么 A ≤ C。

A ≤ B B ≤ C ⇒ A ≤ C

层级中常依赖传递性推导祖先关系。

3. Incomparability（不可比较）

偏序与 total order（全序）的关键区别：并不是任意两个节点都必须能排出上下。

狗 IS_A 动物 猫 IS_A 动物 但： 狗 不是 IS_A 猫 猫 也不是 IS_A 狗

狗和猫在这个 IS_A order 中可以是 incomparable（不可比较）的。

4. “不可比较”不等于“来自不同轴”

这两个概念要严格区分：

狗 vs 猫 → 同一个 IS_A hierarchy 中不可比较 Advantage vs Relationship → 本来就属于不同 facet → 不是“同一个偏序里的两个不可比较节点”那么简单

前者共享同一种 relation system；后者首先要拆分 relation / facet。

5. Multiple Parents（多父节点）

一个节点可以同时拥有多个直接上位节点，只要它们使用的是同一种 hierarchy relation。

A ─┐ ├→ C B ─┘

这种结构不再是 Tree，但仍可以是 DAG / finite poset representation。

6. Multiple Parents 与 Facet 不能混淆

同一种 relation： C IS_A A C IS_A B → Multiple Parents → DAG 不同 facet： Advantage VALUE_OF Relative Effect Relationship VALUE_OF Locus → 不是 multiple inheritance → Faceted Model

判断多父节点之前，必须先确认两条父边是同一种 Relation Type。

7. Cycle（环）通常是层级冲突信号

A IS_A B B IS_A C C IS_A A

若 A、B、C 被认为是不同概念，这与反对称层级直觉冲突。常见解释：

  • 节点其实等价 / 重复命名；
  • 某条边 Relation Type 判错；
  • 结构中出现了真正的建模错误。

8. Hasse Diagram（哈斯图）思维

层级展示时，不需要把所有可由传递性推出的祖先边都画出来。

A → B → C 已知传递性可推出： A → C 但图中通常只保留： A → B B → C

这种“只显示最近直接关系”的思维，可以显著降低知识图的视觉噪音。

9. Direct Parent（直接父节点）不是所有 Ancestor（祖先）

金毛犬 → 狗 → 哺乳动物 → 动物 直接上位： 狗 祖先： 狗、哺乳动物、动物

构建层级时，优先记录 direct relation；更高祖先由 transitivity 推导。

10. Tree 与 DAG 的正式边界

结构直接父节点是否允许不可比较是否允许多父
Tree每个非根节点恰有一个允许不允许
DAG / Poset graph可以有多个允许允许

11. 一个极重要的判断顺序

① Relation Type 一样吗？ ↓ ② 是否具备 hierarchy / order 语义？ ↓ ③ 是否存在 cycle？ ↓ ④ 是否允许 multiple parents？ ↓ ⑤ 是否有 incomparable nodes？ ↓ ⑥ 决定 Tree 还是 DAG ↓ ⑦ 只显示 direct / cover relations

12. 到这里，你已经能判断大多数“层级”问题

现在只剩最后一个实用收尾模块：

Current-node Localization（当前节点定位） Conflict / Unknown Marking（冲突 / 未确定标记） ↓ 把一个具体概念放回整个知识结构里

完成这一模块后，就可以停止扩展理论，开始高浓度 Markdown 归档与 Skill 设计。
