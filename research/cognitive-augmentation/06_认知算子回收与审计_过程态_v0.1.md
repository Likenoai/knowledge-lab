## 1. 为什么启动本轮审计

旧运行架构已经区分：

```text
Shared Cognitive State
→ Control Policy
→ Cognitive Operator
→ Candidate Result
→ Evidence
→ State Update Rule
→ New Shared Cognitive State
```

但旧 Operator 列表存在层级混杂：

- Process、State Object、Operator、Reasoning Method、Acquisition Action、Interface / Representation 被平铺在一起；
- 部分候选 Operator 彼此包含或只是 subtype；
- 部分真正影响认知运行的动作尚未显式进入 Operator Library；
- Human–AI 协作需要的不只是“理论最原子”的操作，还需要有稳定 control semantics 的复合操作。

因此当前目标不是尽快定稿，而是恢复一套层级清楚、可测试、可删减的工作模型。

---

## 2. 当前已经建立的层级区分

### 2.1 Inquiry

`Inquiry（探究）` 当前视为完整受控求知过程，不是单个 Operator。

### 2.2 Cognitive State / Representation

例如：

- Concept
- Question
- Hypothesis
- Evidence
- Model

这些是认知对象 / 状态内容，不是 Operator。

### 2.3 Cognitive Operator

回答：

> 下一步希望当前认知状态 / 表征发生什么变化？

Operator 描述的是 target transformation（目标变换）。

### 2.4 Reasoning Method

例如：

- Deduction
- Induction
- Abduction
- Causal Reasoning
- Counterfactual Reasoning

回答：

> 这个变换中的推断凭什么成立？

当前关键区分：

```text
Operator = WHAT transformation
Reasoning Method = HOW inference
```

因此 Deduction / Induction / Abduction 不与 Clarification / Validation 等 Operator 平铺。

### 2.5 Acquisition / Action

例如：

- Search
- Retrieve
- Ask
- Experiment
- Act

主要负责获得外部材料、执行动作或改变环境。

### 2.6 External Representation / Interface

例如：

- Markdown
- Graph
- HTML
- Table
- Reasoning View

这些是外化后的介质 / 展示实现，不自动等同于认知 Operator。

## 4. 已完成的独立性审计

### 4.1 Clarification

当前判断：保留，Atomic-ish Operator 候选。

核心转换：

```text
存在阻塞性含混的表达 / 问题 / 概念
→
解释边界更稳定、足以继续认知工作的表征
```

### 4.2 Scope Refinement

当前判断：不保留为顶层独立 Operator。

理由：

- 缩小对象、时间、环境、条件、目标，本质属于 Scope Clarification；
- 删除 Scope Refinement 后，Clarification 可以无明显损失地承担其转换职责。

当前归属：

```text
Clarification
└─ Scope Clarification
```

### 4.3 Presupposition Clarification vs Presupposition Check

当前边界：

```text
Presuppositional Clarification
= 把隐藏前提显式化

Presupposition Check
= 检验该前提是否成立
```

因此二者不能仅因名称接近而合并。

但 Presupposition Check 是否应作为 primitive operator 仍待进一步审计。

### 4.4 Concept Explication

当前判断：保留，但不视为 primitive operator。

它通常组合：

- Clarification
- 边界识别
- 相邻概念对比
- Recognition Criteria
- Positive / Negative Examples
- 必要时 Conceptual Engineering

因此更适合：

> Composite Cognitive Operator / Cognitive Protocol

它仍然有高 Human–AI control utility：Human 可以用一个稳定调用词触发一组认知行为。

### 4.5 Problem Framing / Reframing

当前判断：保留为 Composite Operator。

独特输出：

> Working Frame

其内部可能包含：

- Observation / Interpretation 分离
- Goal / scope clarification
- Presupposition check
- Candidate frame generation
- Fit / Discriminability / Decision Leverage 比较
- Working Frame selection

因此不是 primitive，但具有独特控制价值。

### 4.6 Question Formation

当前判断：保留，primitive / near-primitive 候选。

关键区别：

```text
Clarification:
Q1 → Q1'

Question Formation:
Problematic Situation / vague unknown → Q1
```

即 Question Formation 创建一个新的可操作 Question representation。

### 4.7 Cognitive Externalization

当前判断：强保留为独立 Operator 候选。

核心转换：

```text
Implicit / transient representation
→
Explicit / manipulable / shareable external representation
```

重要修正：

> Externalization ≠ Fixation。

外化内容默认仍可修改；真正需要警惕的是 Premature Canonization / Formalization（过早正式化），而不是过早外化。

Reasoning View、HTML、Graph、Markdown 等只是 Externalization 的不同实现 / medium，不等同于 Operator 本身。

## 5. Reasoning Method 与 Operator 的边界

当前审计结论：

### 5.1 Alternative Generation ≠ Abduction

`Alternative Generation` 的目标是扩大候选空间。

它可以使用：

- Abduction
- Analogy
- Retrieval
- Simulation
- Creative generation

Abduction 是解释性假设生成的一种 Reasoning Method，不等于 Alternative Generation Operator。

### 5.2 Implication ≠ Deduction

`Implication` 描述认知任务：

> 若当前命题 / 模型成立，会产生哪些后果、预测或新问题？

Deduction 是完成这一任务的一种推理方法。

### 5.3 Revision / Update ≠ Induction

Induction / Bayesian Update 等可能是更新依据或方法。

但 State Revision 是更上层的状态更新动作。

进一步结合既有运行架构后，当前更倾向：

> Revision / Update 属于 State Update Rule Layer，而不是 Cognitive Operator Layer。

因此旧架构的：

```text
Candidate Result
→ Evidence
→ Update
→ New State
```

应该继续保留，不把 Update 强行塞回 Operator Library。

## 6. 第二轮审计：当前新增判断

### 6.1 Causal Inquiry

当前判断：不作为 primitive operator 冻结。

理由：

- “把问题变成因果问题”可以由 Question Formation / Problem Framing 指向特定 relation type 完成；
- 真正执行因果判断时调用的是 Causal Reasoning（方法层）；
- 因此 Causal Inquiry 更像 Question Formation / Framing 的 specialization 或 composite inquiry move。

暂定：

```text
Question Formation / Problem Framing
└─ causal-targeted specialization
```

而不是 L0 primitive。

### 6.2 Mechanism Inquiry

当前判断：与 Causal Inquiry 类似，不作为 primitive operator 冻结。

“追问中间机制”本质是将 Question 的目标 relation 指向 mechanism。

Mechanistic Reasoning 属于 Method Layer；Mechanism Inquiry 更适合作为 Question Formation / Framing specialization。

### 6.3 Implication

当前判断：保留为 basic operator 候选。

核心转换：

```text
Claim / Hypothesis / Model
→
Consequences / Predictions / New derived questions
```

其执行可调用 Deduction、Causal Model、Counterfactual Reasoning 等不同 Method，因此具有独立 Operator 价值。

### 6.4 Validation

当前判断：保留，但更像 Composite Evaluation Operator，而非 primitive。

它通常需要：

- 生成可检验预测
- 选择边界 / 反例 / 新输入
- 获取证据
- 比较预期与观察
- 输出支持 / 失败 / 边界状态

因此 Human–AI 控制价值高，但内部并非原子。

### 6.5 Transfer

当前判断：从 primitive list 降级。

Transfer 往往组合：

- mapping / analogy
- application
- validation in a new context
- adaptation

因此更像 Composite Evaluation / Generalization Protocol，不适合作为 L0 primitive。

### 6.6 Cognitive Externalization vs Interface

进一步确认：

- Externalization = cognitive transformation；
- Markdown / Graph / HTML / Table / Reasoning View = externalization medium / interface form。

因此 Externalization 继续保留在 Operator Layer。

## 7. 新发现：Compare / Contrast 可能是旧列表遗漏的 primitive candidate

在审计 Discrimination 时发现：

`Discrimination` 往往需要：

```text
Implication
→ derive predictions / consequences

Compare / Contrast
→ locate differences

Evidence Seeking
→ identify discriminating evidence
```

这意味着 Discrimination 可能是一个 Composite Operator，而 `Compare / Contrast` 本身反而具有更基础的独立转换职责：

```text
Representation A + Representation B (+ ...)
→
explicit similarities / differences / ordering / contrast structure
```

当前状态：

> Compare / Contrast = Missing Primitive Candidate，待正式独立性测试。

---

## 8. 新发现：Discrimination 可能应从 primitive 降为 composite

当前工作假设：

```text
Discrimination
≈ Implication
+ Compare / Contrast
+ Evidence Seeking
```

因此它仍有高 Human–AI control utility，但可能属于 L1 Composite Operator，而不是 L0 Primitive。

待后续测试：
- 删除 Discrimination 后，以上组合是否能无损复现其行为？
- 独立保留 Discrimination 是否显著改善控制语义与调用稳定性？

---

## 9. 新发现：Presupposition Check 可能也是 composite

当前工作假设：

```text
Presupposition Check
≈ Presuppositional Clarification
+ Validation
```

因此其 primitive status 不稳定。

待检验：
- 若前提已显式，是否 Validation 足够？
- 若前提未显式，是否 Clarification + Validation 可完整替代？
