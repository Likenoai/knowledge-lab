Knowledge Structure Mapping · Structure Representation

Tree / DAG / Faceted Model / Labeled Graph

Node Type 和 Relation Type 解决“节点是什么、边是什么”；Structure Representation（结构表示）解决第三个问题：整组知识应该用什么形状来表示？

1. 不要先选图形

错误顺序： “我想画一棵树” → 强行寻找父子关系 正确顺序： Node Type → Relation Type → 观察整体关系模式 → 再选 Representation

图形不是知识结构本身；图形只是对已识别关系的表示。

2. Tree（树）

适合主要由同一种层级关系组织，并且每个非根节点只有一个直接父节点的情况。

动物 ├─ 哺乳动物 │ ├─ 狗 │ └─ 猫 └─ 鸟类

Tree 的优势是清晰、导航成本低；代价是表达能力弱，容易把“多父节点”或“多种关系”压扁。

3. DAG（Directed Acyclic Graph，有向无环图）

当关系仍然主要是同一种 hierarchy relation（层级关系），但一个节点允许有多个直接上位节点时，Tree 不够了。

A ─┐ ├→ C B ─┘ C 同时受 A、B 两个上位节点约束 / 归属

DAG 允许 multiple inheritance（多重上位），但仍然要求没有有向环。

Tree 可以看作 DAG 的一个更严格特例。

4. Faceted Model（分面模型）

当一个对象需要从多个彼此独立的描述轴来描述时，不应该把这些轴的取值混成一棵树。

Premise Architecture Locus（改变落点） ├─ Character ├─ Relationship └─ World / Rule Operation（变化方式） ├─ Add ├─ Remove └─ Transform Relative Effect（相对效应） ├─ Advantage ├─ Disadvantage └─ Trade-off

这里 Character、Transform、Advantage 不是 siblings（同级兄弟）；它们来自不同 facet（分面）。

5. Labeled Graph（带标签关系图）

当同一组知识里同时存在多种关系类型，例如 IS_A、PART_OF、PRECEDES、CAUSES、ASSOCIATED_WITH，就应显式给边加标签。

重生 → ENABLES → 信息优势 信息优势 → ASSOCIATED_WITH → 戏剧性反讽 Premise Analysis → PRECEDES → Plot Analysis 角色资产抽取 → PART_OF → 影视生产工作流

此时强行画成一棵树，会丢失真正的语义。

6. 四种结构的选择逻辑

情况优先表示关键条件
单一层级 + 单父节点Tree每个节点只有一个直接父节点
单一层级 + 多父节点DAG允许 multiple inheritance；无环
多个独立描述轴Faceted Model每个 facet 回答不同分类 / 描述问题
多种关系混合Labeled Graph边需要显式 Relation Type

7. 一个更准确的理解：这些不是互斥“世界”

真实知识系统常常是组合结构：

一个 Labeled Graph 内部包含： - 某个 IS_A 子图：DAG - 某个流程子图：PRECEDES chain - 某个对象描述区：Faceted Model - 某个局部导航视图：Tree

所以“选 Tree 还是 Graph”并不是一次性全局二选一，而是选择当前任务最合适的表示层。

8. Representation 与 Ontology 的区别

Ontology / Model（本体 / 模型）决定节点和关系的语义。

Representation（表示）决定这些语义如何被呈现给人或系统。

Semantics first. Representation second. 先决定“是什么关系” 再决定“画成什么样”

9. 当前项目中的直接例子

错误：

Premise Architecture ├─ Advantage ├─ Transformation ├─ Relationship └─ World-Rule

问题：这些节点来自不同 facet，伪装成同级。

修正：

Premise Architecture ├─ Locus │ ├─ Character │ ├─ Relationship │ └─ World / Rule ├─ Operation │ ├─ Add │ ├─ Remove │ └─ Transform └─ Relative Effect ├─ Advantage ├─ Disadvantage └─ Trade-off

这里本质上是 Faceted Model；如果再加入因果、流程、关联关系，就进一步升级成 Labeled Graph。

10. 最小决策框架

① 关系是不是主要只有一种层级关系？ 是 → 继续看是否多父节点 单父 → Tree 多父 → DAG ② 是否存在多个独立描述轴？ 是 → Faceted Model ③ 是否混合多种 Relation Type？ 是 → Labeled Graph

11. 下一节点

Structure Representation 之后，下一步将进入：

Sibling Check（同级检查） + Single-axis Check（单轴检查） + Partition Claim Check（划分声明检查）

也就是：当你准备把 A / B / C 放在同一层时，怎样判断它们真的有资格并列。
