Knowledge Structure Mapping · Lesson 0003

Node Typing（节点定型）

这一课只训练一个问题：节点已经找出来之后，它到底是什么类型的东西？

1. 为什么 Node Extraction 之后还要 Typing？

因为两个词都能成为节点，并不意味着它们可以直接并列。

Relative Effect Advantage

两者都可以是节点，但前者更像 Dimension / Facet（维度 / 分面），后者更像 Value（取值）。如果忽略节点类型，就很容易制造“伪同级”。

Node Typing 的作用：
先判断“这个节点是什么类型”，再判断它和其他节点能否形成同级、上下位、取值或组成关系。

2. 当前项目使用的 7 类 Node Type

Node Type判断问题示例
Instance（实例）这是一个具体对象 / 个案吗？某一部具体短剧、某一个角色
Class / Concept（类 / 概念）这是一个一般概念或一类对象吗？重生题材、优势
Dimension / Facet（维度 / 分面）这是描述对象的一条观察轴吗？Relative Effect、Cost
Value（取值）这是某个 Dimension 上的一个具体状态 / 类别吗？Advantage、Disadvantage
Component（组成部分）这是某个整体内部的组成单元吗？工作流中的一个模块
Process / Stage（过程 / 阶段）这是一个过程或过程中的阶段吗？Research、Synthesis
Relation（关系）它主要是在连接两个节点吗？CAUSES、PART_OF、PRECEDES

3. 一个重要修正：角色、机制不是必须新增的 Node Type

我们之前说过“Entity / Actor（实体 / 行动者）”“Mechanism（机制）”。这些词可以描述节点的语义角色，但当前正式 Node Type 体系里没有单独把它们列成顶层类型。

“主角” → 通常先定为 Instance（具体角色实例） “重生” → 可能是 Class / Concept → 也可能在某个事件模型中被建成 Process / Stage → 具体取决于建模目的 “机制” → 更像节点在当前解释中的功能角色 → 不一定需要新增成第 8 类 Node Type

4. 最容易混淆的一组：Dimension vs Value

这是我们当前最重要的训练点。

Relative Effect（相对效应） ├─ Advantage（优势） ├─ Disadvantage（劣势） └─ Trade-off（交换 / 代价）

这里：

Relative Effect = Dimension Advantage / Disadvantage / Trade-off = Value

判断口诀：

Dimension 回答：“我们在比较 / 描述什么轴？”
Value 回答：“这个轴上当前是什么状态 / 类别？”

5. 同一个词，类型可能因任务改变

例如“重生”：

研究题材分类： 重生 = Class / Concept 研究一部具体剧情： “主角在第 1 集发生重生” 重生 = Process / Event-like node（可按过程 / 阶段建模） 研究某个具体作品： 《某重生短剧》 = Instance
Node Typing 不是给词永久贴标签，而是在当前模型里判断它承担什么类型。

6. 第三课的最小判断流程

找到候选节点 ↓ 这是具体个体还是一般概念？ ↓ 它是观察轴，还是这个轴上的取值？ ↓ 它是整体中的组成部分，还是过程中的阶段？ ↓ 它其实是不是一条 Relation？

7. 练习

请对下面 6 个节点定型。只需要写“节点 → 类型 + 一句理由”。

① 主角“林凡”
这是一个具体角色，还是一般角色类别？
② 重生题材
它是某一部作品，还是一种一般概念 / 类？
③ Relative Effect（相对效应）
它是一种具体状态，还是一条观察轴？
④ Advantage（优势）
它是观察轴，还是轴上的一个取值？
⑤ Research → Synthesis 中的 Research
它更像概念，还是流程阶段？
⑥ CAUSES（导致）
它是节点内容，还是连接两个节点的关系？

8. 本课只带走一句话

Same nodehood does not imply same type.
“都能成为节点”不等于“它们是同一种节点”，更不等于“它们可以并列”。
