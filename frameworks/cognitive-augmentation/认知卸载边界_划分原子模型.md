# 认知卸载边界：划分原子模型

> 状态：Working Framework v0.1
>
> 目标：为 Human Cognitive System Augmentation（人类认知系统增强）建立可操作的边界模型，判断一个具体认知操作应当：
> - 保留在人内；
> - 由工具 / AI 辅助；
> - 部分卸载；
> - 高度自动化。
>
> 本框架不是把“记忆 / 推理 / 决策”等整类能力永久分成可卸载和不可卸载，而是对**具体认知操作**逐项判定。

## 1. 分析单位：Cognitive Operation（认知操作）

定义：

> 一个最小可分析认知操作，是把某种输入表征在一个明确任务条件下转换为输出表征、判断或行动的过程。

形式：

```text
Input Representation
        ↓
Cognitive Operation
        ↓
Output Representation / Judgment / Action
```

例：

```text
“明天下午 3 点有会议”
→ 保持未来意图
→ 到时提醒自己
```

这里“未来意图保持”可以单独分析是否适合卸载到日历 / 提醒器。

## 2. 两个坐标系必须分开

### 2.1 Process Stage（过程阶段）

Parasuraman, Sheridan & Wickens 的经典 human–automation 模型把自动化功能分成四类：

1. Information Acquisition（信息获取）
2. Information Analysis（信息分析）
3. Decision / Action Selection（决策 / 行动选择）
4. Action Implementation（行动执行）

这个坐标回答：

> **认知操作发生在流程的哪里？**

### 2.2 Allocation Atoms（配置原子）

配置原子回答：

> **这个操作在当前人—工具—情境下应该由谁承担、承担多少？**

两者不能混淆。

## 3. 九个划分原子 v0.1

### A1. Normative Load（规范 / 目标负载）

问题：

> 该操作是在执行既定目标，还是在决定“什么值得追求、什么应该做、谁承担后果”？

低：
- 检索一个已知事实；
- 按既定规则排序。

高：
- 选择人生目标；
- 价值冲突裁决；
- 道德责任判断；
- 最终承诺。

初始方向：

> Normative Load 越高，越不适合把最终权威完全卸载给外部系统。

---

### A2. Formalizability（可形式化程度）

问题：

> 输入、输出、约束和成功标准能否被清楚表示？

高：
- 数值计算；
- 格式转换；
- 明确规则检验。

低：
- 模糊的人际关系判断；
- 尚未形成概念的问题；
- 强依赖隐性语境的任务。

初始方向：

> 可形式化程度越高，越容易可靠卸载。

---

### A3. Verifiability（可验证性）

问题：

> 外部系统给出结果以后，人能否以低成本独立判断它是否正确？

高：
- 算式可以复算；
- 代码可以测试；
- 引文可以查证。

低：
- 高度专业、用户自身无法判断的建议；
- 长期结果才能知道对错的战略判断。

初始方向：

> 高可验证性显著提高安全卸载空间。

---

### A4. Embodied / Experiential Grounding（具身 / 第一人称经验依赖）

问题：

> 该操作是否必须依赖主体自己的身体状态、感受、长期互动经验或第一人称价值体验？

高：
- 疼痛与疲劳体验；
- 自己对关系的感受；
- 某些运动控制；
- 与个人价值直接相关的体验判断。

低：
- 文档检索；
- 算法计算；
- 结构化数据整理。

初始方向：

> 具身 / 第一人称依赖越高，越难完整外部化。

---

### A5. Learning / Internalization Value（学习 / 内化价值）

问题：

> 自己完成这个认知操作，是否是在形成未来仍需要的内部能力？

高：
- 初学编程时建立 debugging schema；
- 学数学时形成数量关系与推理结构；
- 学写作时形成语言与结构感。

低：
- 已掌握原理后的机械格式转换；
- 重复性数据录入。

初始方向：

> 即使工具能做，Internalization Value 高时也不应默认完全卸载。

这是“可自动化”与“应该自动化”的关键分界。

---

### A6. Consequence Severity & Reversibility（后果严重度与可逆性）

问题：

> 一旦外部系统出错，损失多大？是否能撤回、修复或补偿？

低：
- 低成本草稿；
- 可撤销排序；
- 可重复计算。

高：
- 不可逆签约；
- 高风险医疗 / 法律 / 财务行为；
- 对他人产生重大影响的行动。

初始方向：

> 高后果 + 低可逆性提高验证、人工监督和多重冗余要求。

注意：

> 这不自动推出“必须由人做”；如果机器显著更可靠，真正需要保留的可能是责任、监督和复核结构，而不是所有计算步骤。

---

### A7. Human Supervisory Capacity（人类监督能力）

问题：

> 当前这个人是否拥有足够内部模型，能够理解、质疑和发现外部系统的错误？

高：
- 专家用 AI 写样板代码并能审查；
- 会计师使用软件计算但理解账务逻辑。

低：
- 完全不懂领域却直接接受 AI 结论。

初始方向：

> 监督能力不足时，“保留最终确认按钮”并不等于真正的人类控制。

此原子用于防止 automation bias（自动化偏误）与 cognitive surrender（认知放弃）。

---

### A8. External System Reliability（外部系统可靠性）

问题：

> 工具在该具体任务上的正确率、稳定性、校准程度和失效模式如何？

必须是 task-specific（任务特定）的。

不能使用：

> “AI 很强”

代替：

> “这个 AI 在该任务上的可靠性已知。”

初始方向：

> 外部系统越可靠且失效模式越可检测，越适合承担更多认知操作。

---

### A9. Coupling Cost（耦合成本）

问题：

> 把任务交给外部工具所需的表达、输入、切换、等待、验证、同步与恢复成本有多大？

包括：

- Prompt / 指令表达成本；
- Context transfer（上下文迁移）；
- Coordination（协调）；
- Latency（延迟）；
- Verification（验证）；
- Failure recovery（失败恢复）。

初始方向：

> 如果使用工具的耦合成本高于内部完成成本，卸载没有实际价值。

## 4. 原子不是静态标签

最重要的工作假设：

> **Offloadability（可卸载性）不是某个认知功能的固定属性，而是一个认知操作在特定 Person × Tool × Context × Time 条件下的状态。**

形式化：

```text
Offloadability
=
f(
  Cognitive Operation,
  Person,
  Tool,
  Context,
  Time
)
```

因此：

```text
同一个“算术”
初学者学习阶段
≠
工程师实际工作阶段
```

同一个“代码生成”：

```text
新手 + 无监督能力
≠
专家 + 测试体系 + 可回滚
```

## 5. 四种初始配置结果

### Human-Core（人内核心）

典型特征：

- Normative Load 高；
- Embodied / Experiential Grounding 高；
- Internalization Value 高；
- 或高风险且当前监督结构不足。

### Human-Led + Tool-Assisted（人主导、工具辅助）

人保留：

- 问题定义；
- 核心表征；
- 判断；
- 验证；
- 最终权威。

工具承担：

- 搜索；
- 草稿；
-比较；
- 计算；
- 局部推理。

### Shared / Adaptive Allocation（共享 / 动态配置）

任务在人和工具之间动态切换。

对应 Adaptive Automation 的“who does what and when”。

### Externalized / Automated（高度外部化 / 自动化）

典型特征：

- Formalizability 高；
- Verifiability 高；
- Normative Load 低；
- Internalization Value 低；
- 后果可逆；
- 工具可靠；
- 耦合成本低。

## 6. 第一版判定矩阵

| 原子 | 倾向保留在人内 | 倾向外部化 |
|---|---|---|
| Normative Load | 高 | 低 |
| Formalizability | 低 | 高 |
| Verifiability | 低 | 高 |
| Embodied Grounding | 高 | 低 |
| Internalization Value | 高 | 低 |
| Consequence / Irreversibility | 高 | 低 |
| Human Supervisory Capacity | 低时需先培养/加冗余 | 高时可安全委托更多 |
| External System Reliability | 低 | 高 |
| Coupling Cost | 高 | 低 |

这不是简单加权总分。

某些原子可以构成 Hard Constraint（硬约束），例如：

- 高风险 + 低可验证 + 低监督能力；
- 高内化价值的学习阶段；
- 高规范负载且涉及不可转移责任。

## 7. 科学依据与边界

### Cognitive Offloading

Risko & Gilbert（2016）将 cognitive offloading 定义为：

> 通过物理行动改变任务的信息加工要求，从而降低内部认知需求。

其综述还指出，是否卸载受到内部认知需求和 metacognitive evaluation（元认知评估）影响，而元认知判断可能错误。

因此“人觉得自己应该卸载”本身不是可靠标准。

### Intention Offloading

Gilbert et al.（2023）综述表明，外部提醒对 prospective memory / intention fulfilment 很有效，但人对何时卸载存在稳定的元认知偏差。

### Human–Automation Function Allocation

Parasuraman, Sheridan & Wickens（2000）指出，自动化可以作用于：

- information acquisition；
- information analysis；
- decision/action selection；
- action implementation；

并且每一类都可以有不同 automation level，而不是“全自动 / 全人工”二选一。

### Adaptive Automation

Adaptive Automation 研究强调：

> function allocation 不只是“谁做什么”，还包括“什么时候由谁做”。

配置可随环境、操作者负荷、能力和系统状态动态变化。

### Automation Risk

Human–AI / automation 研究表明，工具会改变人的活动本身，而不仅是替代操作；过度依赖可能产生 automation bias、situation awareness 损失和 skill degradation。

因此：

> 认知增强的目标不是 Maximum Offloading，而是 Optimal / Adaptive Cognitive Allocation（最优 / 自适应认知配置）。

## 8. 当前待验证问题

v0.1 仍需继续检验：

1. 九个原子是否相互独立，是否存在冗余；
2. Novelty / Context Volatility（新颖性 / 情境波动）是否需要成为第十个原子，还是可由 Formalizability + Reliability 表示；
3. Accountability（责任）是否应从 Normative Load 中独立出来；
4. Privacy / Security 是否属于认知配置原子，还是部署约束；
5. 如何给九个原子建立可操作量表；
6. 哪些组合构成 Hard Constraint，而不能简单加权。
