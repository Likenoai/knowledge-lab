# 原则组合与生成规则

> 状态：Working Framework v0.1
>
> 目的：说明不同现实条件、基础命题与行动原则如何组合，生成更高杠杆的 Derived Principle（派生原则）或 Composite Principle（组合原则）。

## 1. 核心判断

原则不是只能独立存在。

多个较底层条件可以共同生成一个新的行动原则：

```text
Condition / Principle A
+
Condition / Principle B
+
Objective / Context
↓
Derived Principle
```

例如：

```text
时间有限
+
认知有限
↓
研究与行动资源稀缺
↓
Marginal Allocation Principle
边际配置原则
```

这里的新原则并不是简单把两个句子拼起来，而是把多个条件共同造成的决策结构压缩成一个可调用规则。

## 2. “更高原则”更准确地称为组合原则

“更高”容易混淆两种意义：

- 更抽象；
- 更能直接指导行动。

组合后的原则不一定更抽象，反而往往更可行动。

因此优先使用：

- **Derived Principle（派生原则）**
- **Composite Principle（组合原则）**
- **Meta-Principle（元原则）**：当它进一步约束其他原则如何被使用、研究或组合时使用。

## 3. 当前已有两个实例

### P-011 Marginal Allocation Principle（边际配置原则）

主要生成关系：

```text
Temporal Finitude
时间有限
+
Bounded Cognition
认知有限
↓
时间、注意与计算资源稀缺
↓
存在机会成本
↓
下一单位资源需要比较边际价值
↓
P-011 边际配置原则
```

### P-010 Recursive Construction Principle（递归构建原则）

主要生成关系：

```text
Bounded Cognition
有限认知
+
Uncertainty
不确定性
+
Statefulness
状态会被行动改变
+
Feedback Availability
能够获得反馈
↓
无法可靠地一次设计终局
↓
先行动获得新信息
↓
把新状态重新作为输入
↓
P-010 递归构建原则
```

这说明原则体系更适合看成一个生成网络，而不是一张平面清单。

## 4. 原则组合不是任意排列组合

不能把所有原则做机械笛卡尔积。

组合必须满足至少三个条件：

### 4.1 Independent Contribution（独立贡献）

每个父原则都必须对新原则的成立提供不可忽略的信息。

可以做 Ablation Test（消融检验）：

> 去掉其中一个父原则，新原则是否会明显改变、变弱或不再成立？

如果不会，它可能不是必要父项。

### 4.2 Decision Delta（决策增量）

组合后必须产生新的判断或行动能力。

如果：

```text
A + B
```

得到的只是 A 或 B 的另一种说法，那么没有必要新增原则。

### 4.3 Marginal Value（边际价值）

新原则必须比单独记住父原则更值得显式调用。

工作判断：

```text
Value(Composite)
-
Value(existing principles)
>
Retention Cost
```

否则应保留推导关系，但不新增前台原则。

## 5. 原则生成需要额外输入

描述性条件本身通常不能直接推出规范性原则。

严格结构应是：

```text
Reality Conditions
+
Objective / Value
+
Context / Boundary
↓
Action-Guiding Principle
```

例如：

```text
时间有限
+
认知有限
+
目标：提高有限研究资源的产出
↓
优先高边际价值研究
```

因此不能把“现实如此”直接写成“所以你应该如此”。

## 6. 原则生成图

建议后续为人生原则维护一个 Principle Derivation Graph（原则生成图）。

节点可以包括：

- Reality Condition
- Foundational Proposition
- Working Principle
- Composite Principle
- Meta-Principle

边只表达：

> **derived from（由……生成 / 约束）**

例如：

```text
时间有限 ─────┐
             ├──> P-011 边际配置原则
认知有限 ─────┘

认知有限 ─────┐
不确定性 ─────┼──> P-010 递归构建原则
状态性 ───────┤
反馈可得 ─────┘
```

原则“如何生成”的图最好保持 DAG（有向无环图）。

而原则应用到研究，再产生新原则，是另一个 Feedback Loop（反馈循环）。

两者应区分：

```text
Derivation Graph
解释一个原则从哪里来

Feedback Loop
解释原则体系如何随实践递归更新
```

## 7. 组合原则的评估方法

对一个候选组合原则 C：

```text
C = f(P1, P2, ... Pn ; Objective, Context)
```

至少检查：

1. 去掉 P1，C 是否仍基本成立？
2. 去掉 P2，C 是否仍基本成立？
3. C 是否产生父原则单独没有产生的行动判断？
4. C 是否比单独记忆父原则更容易调用？
5. C 是否与现有原则重复？
6. C 是否在个人现实场景中有足够高的预期使用价值？

只有通过这些问题，才值得进入原则注册表。

## 8. 防止组合爆炸

如果有 8 个底层条件，机械枚举组合会迅速爆炸。

因此不采用：

```text
先枚举所有组合
→ 再筛选
```

而采用：

```text
真实高价值问题
↓
哪些已有条件共同解释它？
↓
能否压缩成新的行动原则？
↓
边际价值是否足够高？
↓
值得才登记
```

这本身就是 P-011 Marginal Allocation Principle（边际配置原则）对原则研究的应用。

## 9. 当前下一步

不继续扩张 taxonomy。

优先做三件事：

1. 给当前 P-001～P-011 标注已知的父条件 / 父原则；
2. 从真实高价值人生决策出发，寻找有明显 Decision Delta 的组合；
3. 对生成出的组合原则使用边际价值门槛，决定显式保留、后台保留、合并或删除。

目标不是得到最多原则，而是得到一个小而强、能够组合生成判断的原则系统。
