## 1. 目标和失败模式

目标不是多写文件，而是让有价值的新结果可被下一轮 Human 与 AI 恢复、共同操作、修正和检验。

先前失效模式：只产生新日志 `06`，却不告知上游 `05` 有后继研究；类似地 `03` 保留早期命名而未指向已修订它的 `04`。下一轮若只读取旧文件，会得到过时的有效状态。

必须区分：

- **Externalization（外化）**：把已有或新出现的认知结构显式呈现，使其可检查、可操作、可修订；不等于固化。
- **Capture（捕获）**：把值得跨轮复用的结构保存为文件。
- **Reconciliation（状态协调）**：确认新结果与既有文件的关系，是补充、修订、否定、取代、冲突还是互不影响。
- **Update（更新）**：让受影响的“当前有效状态”反映新的判断；保留历史推导的可追溯性。
- **Reuse（复用）**：下一轮真正读取更新后的状态，而非凭旧印象继续推理。

## 2. 什么情况下 AI 应主动外化

至少满足一个具有明确后续价值的条件：

1. 关键概念关系或工作模型已开始跨轮反复重建，继续依赖散落对话会造成漂移；
2. 出现需要共同查看、对照、重排、排错或修订的表征结构；
3. 新证据/判断会改变旧模型、原则、当前研究焦点或承诺；
4. 工作即将暂停或切换主题，重要状态需要在下次准确恢复。

如果只是一次性问题或外化没有带来额外认知价值，直接回答即可。

**主动权分配**：
- 临时对话内草图/简短工作状态：AI 可直接给出；
- 新的持续维护文件与较大范围变更：AI 先说明价值和影响；用户明确授权时直接执行；
- 正式规范化、重要承诺与不可逆操作：保留用户最终确认权。
- 持久化到仓库不等于把暂定假说宣布为 Canonical；用成熟度和来源区分。

## 3. 四阶段闭环（最小执行单位）

### 3.1 Capture

记录最小可复用结构：研究目标、当前结论及其成熟度、关键理由/证据、仍未解决的点、下一步入口。优先更新相关旧文件，确需保留研究过程时另建 Working Log。

### 3.2 Reconcile / Impact Check

在提交新记录前，回答：

- **影响谁**：哪些既有文件、原则或承诺会因新结果被误读或需要改变？
- **影响方式**：补充 / 修订 / 否定 / 取代 / 仍有冲突 / 无影响？
- **实际处理**：修改当前有效版本；或给历史快照添加简短的“后继版本 / 已修订”提示和链接，保留旧正文。
- **未更新原因**：如确实不需回写，应明确记为“无直接影响”；禁止默认静默略过。

### 3.3 Verify

写入后重新读取，不以“准备提交”或工具返回部分成功代替验证。最低核验：

- 文件实际存在且内容符合本轮结论；
- 关联旧文件的状态和后继链接已更新；
- 不存在旧“当前结论”与新结论并列却无版本关系的情况；
- 工具失败时如实标记失败，列出待补操作。

### 3.4 Reuse

开始下一轮有延续关系的研究时，优先读取“当前有效状态/最新工作日志”与相关旧文件，再选择 Operator。对旧版本被新版本取代的情况，遵循后继链接。没有执行复用，就尚不能宣称完成跨轮认知闭环。

## 4. 对旧文档的回写方式

- **历史快照**：保留推导原文；页首加入“Historical / Superseded by / Updated in”标记和后继文件链接。
- **仍有效的工作文件**：局部更新相关结论、当前未决问题及证据来源，必要时追加短的 Changelog。
- **原则注册表**：只更新最精简核心表达、状态、触发条件和详细文档链接。
- **研究过程日志**：记录每轮被保留/否定的判断、对旧文件的影响与处理状态，而不是复制所有长答案。
- **交互状态文件**：只记录正在生效的交互模式与规范入口，不把整份理论塞进去。

## 6. 停止规则与边界

- 当新结果不足以改变旧文件的有效性或后续行为时，可只在现有文件做轻量补充，不机械联动全仓库。
- 不为每个细小新想法建一个正式原则，不强行把历史文件全文改写成新版本。
- 不能把对话中未受外部证据支持的工作推导包装成已验证科学结论。
- 不用格式美观、文件数量或新增 commit 次数衡量认知收益；以**可恢复性、冲突减少、正确继续研究**衡量。
- 验证持久化文件不等于已验证 AI 跨会话自动读取；需通过下一轮实际复用检验。
