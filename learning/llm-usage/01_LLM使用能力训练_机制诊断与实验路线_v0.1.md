# LLM 使用能力训练｜从 Prompt 试错到可证据化的任务诊断

> 日期：2026-10-14 · **状态：Working Training Protocol / 待实操验证**  
> 适用角色：ChatGPT/LLM 使用者；扩展到 Agent 开发。  
> 关联：`learning/ROADMAP.md` 中 Epistemic Loop + Mastery Loop。不是替代原路线。  
> 内容性质：课程设计与使用原则属于教学/工程综合提案；单条研究发现不等于对 GPT-6 或所有 LLM 的普适保证。

## 一、研究起点

用户提出的问题：**为什么同一个 LLM 在模型权重固定时，不同 Prompt 可以让模型表现出差异巨大、仿佛“唤醒不同能力”的行为？**

目前的精确工作表述：

> Prompt 提供任务条件、约束、示例和信息结构，改变固定参数模型推理时的内部计算状态，使其在当前输入上组合、运用训练中形成的计算能力；也可能只是补充缺失信息、改善输出协议或减少歧义。不能从输出差异直接断定内部能力被激活。

### 必须区分的六种解释

1. **任务识别**：原任务不明确，模型没有确定要做什么。
2. **能力调用/表征适配**：任务信息影响模型相关内部计算；局部证据见任务向量/函数向量研究，但不把“唤醒”当成独立模块事实。
3. **计算组织**：分解问题、明确检查流程、通过外部状态降低复杂度。
4. **信息补充**：加入事实、示例、外部证据，不是只换措辞。
5. **输出协议**：结果结构、格式、可核验性提高，但不自动等于推理能力提升。
6. **能力/工具缺口**：模型本身缺乏所需知识、计算可靠性或工具；改 Prompt 无法保证成功。

## 二、长期能力目标

1. 识别任务的成功判据，而不是只判断回复是否流畅。
2. 在信息缺失、任务不清、策略不合适、模型能力不足之间提出可检验的竞争解释。
3. 能够选择最小有意义干预：重写目标/补资料/给示例/拆任务/加工具/切模型/建立评测。
4. 能够用控制变量、小样本测试与反例检验干预是否奏效。
5. 能把局部经验迁移到个人 ChatGPT 使用和可观测 Agent 工作流。
6. 能解释 Transformer 前向传播、Task Conditioning、ICL 的理论界限，不把运行时上下文改变混同权重训练。

## 三、六阶段研究与训练

| 期 | 核心问题 | 达标行为 |
| --- | --- | --- |
| M1 任务表征 | 模型到底要完成什么？ | 写出目标、输入、范围、判断标准、不可假设的内容 |
| M2 失败归因 | 为什么当前 Prompt 无效？ | 提出至少两个可检验解释，识别应先改哪一层 |
| M3 有效干预 | 改指令、示例、上下文还是拆任务？ | 做最小变更并描述预期影响 |
| M4 Prompt 评测 | 如何证明改善且没有副作用？ | 同题成对比较，设计负例与未见案例 |
| M5 Agent 迁移 | 用哪些工具、记忆、状态与反馈？ | 区分运行时修复与长期 Skill/Policy 修订 |
| M6 机制理解 | 权重固定，内部变化在哪里？ | 理解激活、Attention、任务向量与因果干预的限度 |

学习法：**真实问题/研究故事 → 学习者初步判断 → 机制与权威证据 → 对照实验 → 反馈 → 新任务迁移**。避免僵硬循环测验与冗长 Prompt 模板；坚持证据与用途挂钩。

## 四、第一节操作｜同一个事实，三种不同的信息条件

固定剧情（示例，可在新聊天重复运行）：

> 凌晨，唐舟从项目办公室取走一块 U 盘，将其藏在书架后的暗格。程砚当晚在医院，没看到取走或藏匿的过程。第二天，程砚只接到同事电话：“U 盘不见了。”随后剧本写道：程砚径直走向书架暗格，取出 U 盘。

### 提示实验
- P0（宽泛）：“分析这段剧情是否合理，指出主要问题。”
- P1（任务结构）：“检查每名角色行动前掌握的信息；把剧情事实与推测分开；找出角色做决定时所依赖却未交代的信息。分类为明确矛盾/信息缺口/无问题；引用原文依据。”
- P2（补充事实）与 P1 相同，但在原剧情追加事实：“程砚离院前曾在手机上查看办公室实时监控，目睹唐舟将 U 盘藏进书架暗格。”

### 实验逻辑
- **P0 对比 P1**：事实固定，只改变任务操作及输出判断标准。若 P1 更明确识别问题，优先归因为任务配置/计算组织，不声称已验证内部表征机制。
- **P1 对比 P2**：任务指令固定，增加角色拥有的信息。新的剧情不再存在同一种信息缺口；改变源自输入事实，而非 Prompt 魔法。
- 可用复述、改格式作为扰动以检查稳定性；不同新聊天运行避免前轮泄漏。保持模型/运行配置尽量一致；对随机回答不下单次结论。

### 本案例的判读基线
- P1 应重点指出**信息缺口**，不是断言剧情必然违反逻辑；片段没有解释程砚如何知道暗格。可以通过补镜头/信息交代修复。
- P2 给出程砚获得信息的证据，消除了这个特定缺口，但剧情仍可能存在其他待验证问题。
- 任务成功不只看“结论说对了”，还看引用证据、没有凭空添加事件、能区分缺口与矛盾。

## 五、证据强度与教学判断

### 当前可靠依据
1. OpenAI Prompt Engineering（官方实践）强调清晰任务、上下文、实例、结构和版本化评测：https://developers.openai.com/api/docs/guides/prompt-engineering
2. OpenAI Reasoning Best Practices：推理模型优先直接清晰的目标、约束和完成标准；“think step by step”并非通用提升：https://developers.openai.com/api/docs/guides/reasoning-best-practices
3. Anthropic Context Engineering（2025）：强调上下文选择，而不是仅优化措辞：https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
4. Min et al. (EMNLP 2022)：示例标签、输入分布、格式的可区分作用，仅对研究设置成立：https://aclanthology.org/2022.emnlp-main.759/
5. Sclar et al. (ICLR 2024)：部分模型对等价 Prompt 格式敏感，不能从单个格式判断整体性能：https://proceedings.iclr.cc/paper_files/paper/2024/hash/6c0e99d736da621403018ca7b32b1a4d-Abstract-Conference.html
6. Liu et al. (TACL 2024)：长上下文信息位置可影响部分模型的检索表现：https://direct.mit.edu/tacl/article/doi/10.1162/tacl_a_00638/119630/Lost-in-the-Middle-How-Language-Models-Use-Long
7. OpenAI Eval/Model Optimization：先明确评测再迭代 Prompt：https://developers.openai.com/api/docs/guides/model-optimization
8. Hendel et al. 2023，Task Vectors，局部机制证据：https://aclanthology.org/2023.findings-emnlp.624/

### 没有被证明的外推
- “角色扮演越夸张越能唤醒能力”不成立为普适原则。
- “Prompt 越长，答案越好”没有普适支持。
- “输出更专业意味着模型调用了更深层推理模块”不能凭黑盒单次回答断言。
- “换 Prompt 没效果说明模型不具备能力”也不能由单次失败断言。

## 六、下次继续的入口与记录办法

- 当前停点：**M1 任务表征**。先完成 P0/P1 的差异诊断，不急于讨论所有技术术语。
- 用户尝试后记录：任务ID、版本、使用的模型、样本文本、修改的变量、观察结果、评分理由、竞争解释、下一步动作。
- 每轮将经验分为 `Observed`（观察到）、`Supported`（有直接证据）、`Hypothesis`（待检验）、`Practice`（有使用价值但未普适验证）。
- 后续优先更新本路线而非创建重复教材；实验结果未经实践不得标记为已掌握。
- Impact Check：与 `learning/ROADMAP.md` 的 Mastery/Epistemic Loop 一致；本文件是专门训练路线，无需替代 ROADMAP。后续若改变长期总体路线再做上游修订。
