# 认知卸载边界：划分原子模型

> 状态：Working Framework v0.2
>
> 目标：用尽可能少、但具有高解释力的原子，判断一个 Cognitive Operation（认知操作）应当保留在人内，还是可以交给外部工具 / AI。

## 1. 基本判断

认知卸载边界不应该由一长串工程变量定义。

像：

- 工具可靠性；
- 可验证性；
- 风险；
- 耦合成本；
- 隐私；
- 可逆性；

这些都重要，但它们更适合放在具体部署与工具选择阶段，不属于“为什么某种认知必须保留在人内”的最本质解释。

因此，本框架只保留两个核心原子。

---

## 2. Atomic Unit：Cognitive Operation（认知操作）

不对“记忆 / 推理 / 决策”整个能力类别做永久划分。

分析单位是：

> **一个可以相对独立描述输入、认知变换与输出的最小认知操作。**

形式：

```text
Input
↓
Cognitive Operation
↓
Output / Judgment / Action
```

同一个操作是否应该外部化，会随人的发展阶段与任务目标变化。

---

# 3. 两个核心划分原子

## A1. Constitutive Ownership（构成性归属）

核心问题：

> **这个认知过程是否本身构成“我作为主体是谁、我要什么、我如何体验和承担后果”的一部分？**

如果答案是“是”，那么外部系统可以帮助，但不应替代人的最终主体位置。

典型包含：

- Goal Formation（目标形成）
- Value Judgment（价值判断）
- Meaning Construction（意义形成）
- First-Person Experience（第一人称体验）
- Identity-Relevant Choice（身份相关选择）
- Responsibility / Commitment（责任与承诺）

它的本质不是“AI 能不能算出来”。

而是：

> **如果把这个认知过程完全移交出去，是否改变了谁在作为 Agent（主体）生活与行动？**

### 判断句

> **凡是认知过程的价值部分来自“必须由我来拥有、体验、选择或承担”，就存在 Constitutive Ownership。**

---

## A2. Internal Capability Requirement（内在能力必要性）

核心问题：

> **即使外部系统可以完成这个任务，我是否仍然必须在自己内部保留足够的认知能力？**

“必须保留”通常不是为了当前这一次结果，而是为了未来：

- Learning（学习）
- Transfer（迁移）
- Independent Judgment（独立判断）
- Supervision（监督）
- Error Detection（错误识别）
- Recovery / Takeover（失效后的接管）
- Novel Situation Handling（新情境处理）
- Embodied Skill（具身技能）

它解释了为什么：

> **Can Automate（能自动化）不等于 Should Fully Offload（应该完全卸载）。**

### 判断句

> **如果不亲自经历或维持这个认知过程，会削弱未来仍需要的内部能力，那么该过程至少应部分保留在人内。**

---

# 4. 一个派生原则：Residual Delegation（剩余委托）

当一个认知操作同时满足：

```text
Constitutive Ownership 低
+
Internal Capability Requirement 低
```

那么：

> **没有本质理由要求它继续占用人的内部认知资源。**

此时进入第二阶段：

> 根据 Comparative Advantage（比较优势）选择由人、工具、AI 或自动化系统执行。

形式：

```text
A1 低
+
A2 低
↓
原则上可外部化
↓
再比较：
Human vs Tool vs AI
谁在当前任务上更有效
```

可靠性、成本、风险、验证难度等变量，都放到这一阶段处理。

它们决定：

> **“用哪个工具、卸载多少、怎样监督”**

而不是决定：

> **“为什么这种认知必须属于人”。**

---

# 5. 四象限

两个原子足以产生第一版边界地图。

| | Internal Capability Requirement 低 | Internal Capability Requirement 高 |
|---|---|---|
| **Constitutive Ownership 低** | **Externalizable**：优先考虑外部化 | **Training / Supervised Delegation**：可以借助工具，但必须保留能力形成与监督 |
| **Constitutive Ownership 高** | **Human-Owned, Tool-Assisted**：工具可以分析，人保留最终主体性 | **Human-Core**：既构成主体性，又需要内部能力 |

## 5.1 Externalizable

例：

- 已掌握原理后的机械计算；
- 日程提醒；
- 格式转换；
- 大规模检索；
- 重复性信息整理。

目标：

> 尽量释放有限的人类认知资源。

## 5.2 Training / Supervised Delegation

例：

- 初学编程时使用 AI；
- 学数学时使用计算工具；
- 尚未形成领域模型时依赖 AI 推理。

这里工具可以参与，但人必须形成足够的内部能力。

## 5.3 Human-Owned, Tool-Assisted

例：

- 职业方向选择；
- 人生目标形成；
- 价值冲突判断。

AI 可以：

- 搜集信息；
- 提供反例；
- 构造选择空间；
- 模拟后果。

但最终“什么值得追求”不能仅因为外部系统计算能力更强就自动转移所有权。

## 5.4 Human-Core

例：

- 形成核心价值；
- 第一人称体验；
- 需要长期保留的关键判断能力；
- 与身份、承诺和责任高度绑定的认知过程。

---

# 6. 为什么这两个原子更本质

原 v0.1 的九个变量实际上可以被重新归类。

### 被 A1 吸收的内容

- Normative Load
- Embodied / Experiential Grounding 中与第一人称体验相关的部分
- Accountability 中与主体承担相关的部分

它们都在回答：

> **这个认知是否构成主体本身？**

### 被 A2 吸收的内容

- Internalization Value
- Human Supervisory Capacity
- Skill Degradation
- Learning / Transfer

它们都在回答：

> **这个能力是否必须继续存在于人的内部？**

### 降级为部署约束的内容

- Formalizability
- Verifiability
- Consequence / Reversibility
- External System Reliability
- Coupling Cost
- Privacy / Security

这些变量仍然重要，但属于：

> **工具选择与系统工程**

而不是：

> **认知边界的本体划分。**

---

# 7. 当前最简判定流程

```text
一个 Cognitive Operation
        ↓
Q1
它是否构成主体的目标、价值、
体验、身份或责任？
        │
      YES
        ↓
人必须保留 Ownership
        │
       NO
        ↓
Q2
未来是否仍需要人自己拥有
这项内部能力？
        │
      YES
        ↓
保留训练 / 理解 / 监督能力
        │
       NO
        ↓
原则上可以外部化
        ↓
再按比较优势选择工具
```

---

# 8. 当前工作命题

> **Cognitive Augmentation（认知增强）不是最大化认知卸载，而是：把必须构成人之主体性、或必须由人长期保有的能力留在人内；把其余认知负担按比较优势分配给外部系统。**

进一步压缩：

> **保留主体性，保留必要能力，其余按比较优势外部化。**

这是当前 v0.2 的核心。
