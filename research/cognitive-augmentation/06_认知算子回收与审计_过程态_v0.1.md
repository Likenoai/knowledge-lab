## 1. 为什么启动本轮审计

旧运行架构已经区分：

```text
Shared Cognitive State
→ Control Policy
→ Cognitive Operator
→ Candidate Result
→ Evidence
→ State Update Rule
→ New Shared Cognitive State
```

但旧 Operator 列表存在层级混杂：

- Process、State Object、Operator、Reasoning Method、Acquisition Action、Interface / Representation 被平铺在一起；
- 部分候选 Operator 彼此包含或只是 subtype；
- 部分真正影响认知运行的动作尚未显式进入 Operator Library；
- Human–AI 协作需要的不只是“理论最原子”的操作，还需要有稳定 control semantics 的复合操作。

因此当前目标不是尽快定稿，而是恢复一套层级清楚、可测试、可删减的工作模型。

## 2. 当前已经建立的层级区分

### 2.1 Inquiry

`Inquiry（探究）` 当前视为完整受控求知过程，不是单个 Operator。

### 2.2 Cognitive State / Representation

例如：

- Concept
- Question
- Hypothesis
- Evidence
- Model

这些是认知对象 / 状态内容，不是 Operator。

### 2.3 Cognitive Operator

回答：

> 下一步希望当前认知状态 / 表征发生什么变化？

Operator 描述的是 target transformation（目标变换）。

### 2.4 Reasoning Method

例如：

- Deduction
- Induction
- Abduction
- Causal Reasoning
- Counterfactual Reasoning

回答：

> 这个变换中的推断凭什么成立？

当前关键区分：

```text
Operator = WHAT transformation
Reasoning Method = HOW inference
```

因此 Deduction / Induction / Abduction 不与 Clarification / Validation 等 Operator 平铺。

### 2.5 Acquisition / Action

例如：

- Search
- Retrieve
- Ask
- Experiment
- Act

主要负责获得外部材料、执行动作或改变环境。

### 2.6 External Representation / Interface

例如：

- Markdown
- Graph
- HTML
- Table
- Reasoning View

这些是外化后的介质 / 展示实现，不自动等同于认知 Operator。

## 4. 已完成的独立性审计

### 4.1 Clarification

当前判断：保留，Atomic-ish Operator 候选。

核心转换：

```text
存在阻塞性含混的表达 / 问题 / 概念
→
解释边界更稳定、足以继续认知工作的表征
```

### 4.2 Scope Refinement

当前判断：不保留为顶层独立 Operator。

理由：

- 缩小对象、时间、环境、条件、目标，本质属于 Scope Clarification；
- 删除 Scope Refinement 后，Clarification 可以无明显损失地承担其转换职责。

当前归属：

```text
Clarification
└─ Scope Clarification
```

### 4.3 Presupposition Clarification vs Presupposition Check

当前边界：

```text
Presuppositional Clarification
= 把隐藏前提显式化

Presupposition Check
= 检验该前提是否成立
```

因此二者不能仅因名称接近而合并。

但 Presupposition Check 是否应作为 primitive operator 仍待进一步审计。

### 4.4 Concept Explication

当前判断：保留，但不视为 primitive operator。

它通常组合：

- Clarification
- 边界识别
- 相邻概念对比
- Recognition Criteria
- Positive / Negative Examples
- 必要时 Conceptual Engineering

因此更适合：

> Composite Cognitive Operator / Cognitive Protocol

它仍然有高 Human–AI control utility：Human 可以用一个稳定调用词触发一组认知行为。

### 4.5 Problem Framing / Reframing

当前判断：保留为 Composite Operator。

独特输出：

> Working Frame

其内部可能包含：

- Observation / Interpretation 分离
- Goal / scope clarification
- Presupposition check
- Candidate frame generation
- Fit / Discriminability / Decision Leverage 比较
- Working Frame selection

因此不是 primitive，但具有独特控制价值。

### 4.6 Question Formation

当前判断：保留，primitive / near-primitive 候选。

关键区别：

```text
Clarification:
Q1 → Q1'

Question Formation:
Problematic Situation / vague unknown → Q1
```

即 Question Formation 创建一个新的可操作 Question representation。

### 4.7 Cognitive Externalization

当前判断：强保留为独立 Operator 候选。

核心转换：

```text
Implicit / transient representation
→
Explicit / manipulable / shareable external representation
```

重要修正：

> Externalization ≠ Fixation。

外化内容默认仍可修改；真正需要警惕的是 Premature Canonization / Formalization（过早正式化），而不是过早外化。

Reasoning View、HTML、Graph、Markdown 等只是 Externalization 的不同实现 / medium，不等同于 Operator 本身。

## 5. Reasoning Method 与 Operator 的边界

当前审计结论：

### 5.1 Alternative Generation ≠ Abduction

`Alternative Generation` 的目标是扩大候选空间。

它可以使用：

- Abduction
- Analogy
- Retrieval
- Simulation
- Creative generation

Abduction 是解释性假设生成的一种 Reasoning Method，不等于 Alternative Generation Operator。

### 5.2 Implication ≠ Deduction

`Implication` 描述认知任务：

> 若当前命题 / 模型成立，会产生哪些后果、预测或新问题？

Deduction 是完成这一任务的一种推理方法。

### 5.3 Revision / Update ≠ Induction

Induction / Bayesian Update 等可能是更新依据或方法。

但 State Revision 是更上层的状态更新动作。

进一步结合既有运行架构后，当前更倾向：

> Revision / Update 属于 State Update Rule Layer，而不是 Cognitive Operator Layer。

因此旧架构的：

```text
Candidate Result
→ Evidence
→ Update
→ New State
```

应该继续保留，不把 Update 强行塞回 Operator Library。

## 6. 第二轮审计：当前新增判断

### 6.1 Causal Inquiry

当前判断：不作为 primitive operator 冻结。

理由：

- “把问题变成因果问题”可以由 Question Formation / Problem Framing 指向特定 relation type 完成；
- 真正执行因果判断时调用的是 Causal Reasoning（方法层）；
- 因此 Causal Inquiry 更像 Question Formation / Framing 的 specialization 或 composite inquiry move。

暂定：

```text
Question Formation / Problem Framing
└─ causal-targeted specialization
```

而不是 L0 primitive。

### 6.2 Mechanism Inquiry

当前判断：与 Causal Inquiry 类似，不作为 primitive operator 冻结。

“追问中间机制”本质是将 Question 的目标 relation 指向 mechanism。

Mechanistic Reasoning 属于 Method Layer；Mechanism Inquiry 更适合作为 Question Formation / Framing specialization。

### 6.3 Implication

当前判断：保留为 basic operator 候选。

核心转换：

```text
Claim / Hypothesis / Model
→
Consequences / Predictions / New derived questions
```

其执行可调用 Deduction、Causal Model、Counterfactual Reasoning 等不同 Method，因此具有独立 Operator 价值。

### 6.4 Validation

当前判断：保留，但更像 Composite Evaluation Operator，而非 primitive。

它通常需要：

- 生成可检验预测
- 选择边界 / 反例 / 新输入
- 获取证据
- 比较预期与观察
- 输出支持 / 失败 / 边界状态

因此 Human–AI 控制价值高，但内部并非原子。

### 6.5 Transfer

当前判断：从 primitive list 降级。

Transfer 往往组合：

- mapping / analogy
- application
- validation in a new context
- adaptation

因此更像 Composite Evaluation / Generalization Protocol，不适合作为 L0 primitive。

### 6.6 Cognitive Externalization vs Interface

进一步确认：

- Externalization = cognitive transformation；
- Markdown / Graph / HTML / Table / Reasoning View = externalization medium / interface form。

因此 Externalization 继续保留在 Operator Layer。

## 7. 新发现：Compare / Contrast 可能是旧列表遗漏的 primitive candidate

在审计 Discrimination 时发现：

`Discrimination` 往往需要：

```text
Implication
→ derive predictions / consequences

Compare / Contrast
→ locate differences

Evidence Seeking
→ identify discriminating evidence
```

这意味着 Discrimination 可能是一个 Composite Operator，而 `Compare / Contrast` 本身反而具有更基础的独立转换职责：

```text
Representation A + Representation B (+ ...)
→
explicit similarities / differences / ordering / contrast structure
```

当前状态：

> Compare / Contrast = Missing Primitive Candidate，待正式独立性测试。

---

## 8. 新发现：Discrimination 可能应从 primitive 降为 composite

当前工作假设：

```text
Discrimination
≈ Implication
+ Compare / Contrast
+ Evidence Seeking
```

因此它仍有高 Human–AI control utility，但可能属于 L1 Composite Operator，而不是 L0 Primitive。

待后续测试：
- 删除 Discrimination 后，以上组合是否能无损复现其行为？
- 独立保留 Discrimination 是否显著改善控制语义与调用稳定性？

---

## 9. 新发现：Presupposition Check 可能也是 composite

当前工作假设：

```text
Presupposition Check
≈ Presuppositional Clarification
+ Validation
```

因此其 primitive status 不稳定。

待检验：
- 若前提已显式，是否 Validation 足够？
- 若前提未显式，是否 Clarification + Validation 可完整替代？

## 14. 2026-10-08｜Synthesis / Integration 独立性审计

> 状态：Working Analysis / Conceptual Ablation（概念消融），尚无真实模型 A/B 或用户研究实测。
>
> 研究恢复依据：本文件第 10–11 节；上游 05 早期候选含 Structure / Synthesize；相邻知识结构研究见 concepts/knowledge-structure-and-explanation-path.md。

### 14.1 审计问题

当前已拥有 Decomposition、Compare / Contrast、Alternative Generation、Implication、Validation、Externalization 与 State Update，是否仍有必要保留 Synthesis / Integration？

判断标准：
1. Cognitive Independence：是否存在有区分度的目标转换及输出？
2. Control Utility：即使可由已有操作组合，是否仍是值得稳定调用的人机协作控制单位？

### 14.2 Synthesis（结构综合）的候选定义

输入：多个部分判断、证据片段、概念或模型（可能互补或冲突）。

目标转换：

~~~text
Partial Representations R1, R2, ... Rn
  → identify relations / constraints / conflicts
  → construct a joint structure
  → Candidate Integrated Model M*
~~~

输出约束：
- 建立新的部分—整体、限制、依赖、因果或其他有意义的语义关系，不能只罗列；
- 保持证据来源、适用范围和未解决的冲突；
- 整体能支持至少一种原先单独片段难以完成的判断、解释、推论或行动；
- 冲突暂不可解时，允许留在模型中，禁止强制虚假的一致性。

**工作定义**：Synthesis 是以构建可工作的联合结构为目标，将多个局部表征在语义与约束上协调、组合并产生候选整体模型的复合认知操作。

### 14.3 邻近算子消融

| 邻近对象 | 能完成的转换 | 无法保证的结果 |
| --- | --- | --- |
| Compare / Contrast | 发现异同与冲突 | 不自动建立统一、可使用的整体模型 |
| Decomposition | 整体拆成部分及其关系 | 不自动完成 parts → whole 的整体构建 |
| Alternative Generation | 形成多个竞争候选 | 不自动整合已有局部证据与交叉约束 |
| Implication | 推出后果、预测 | 未必形成跨部分的联合结构 |
| Validation | 检查某模型与证据/反例的关系 | 不自动建构替代联合模型 |
| Knowledge Structure Mapping | 明确节点类型、关系与结构 | 与 Synthesis 高度重叠；是否独立仍待跨任务测试 |
| Externalization | 使结构外显、可共同操作 | 外显的图表本身不保证新语义整合 |
| State Update | 使经审议的候选结果进入有效状态 | Synthesis 的产物 M* 仍是 Candidate，不自动被采纳 |

**消融限制**：用 Compare + Structure Mapping + Alternative Generation + Validation 等组合，并加入“形成联合模型”的目标约束，可能复制 Synthesis 的输出。因此本轮不能认定 Synthesis 是不可约的 Primitive Operator。

### 14.4 三个思维实验（仅逻辑对照，非实测）

A. 注册增长、收入持平、不同 cohort 的支付时间不同：并排列出事实不是 Synthesis；建立「获客 → 分群 → 支付转化 → 收入确认时间」并明确缺失数据的结构才更接近 Synthesis。不能直接断言用户质量下降。

B. 结合本课题中的三个约束：Operator 产生 Candidate Result；Externalization 使表征可操作但不等于正式化；新结果可能需要协调更新旧状态。可综合为：

~~~text
Operator → Candidate Result
→ optionally Externalize
→ Evaluate / Reconcile
→ authorized persist if warranted
→ State Update → Subsequent Reuse
~~~

注意：外化不等于被承认为新的有效共享认知状态。

C. 两份证据结论冲突：Synthesis 应先检查任务、人群、测量、时间等条件能否解释差异；无法解释则保留 unresolved conflict，禁止杜撰统一理论。

### 14.5 Integration（整合）的歧义拆分

- Structural Integration（结构整合）：多个局部表征形成联合知识结构；可属于 Synthesis 的过程或结果，不另设同级算子。
- Epistemic / State Integration（认识/状态整合）：将证据支持的新结果纳入有效认知状态；属于 State Update / Reconciliation Layer。
- Cognitive Integration（认知整合）：上游 05 中 Human–AI 持续协调和互补形成的系统性质；不是单次 Operator。

因此不把 Integration 与 Synthesis 当作两个并列的原子算子。

## 15. 2026-10-08｜Synthesis vs Knowledge Structure Mapping vs Compare 跨任务对照

> 状态：Working Cross-task Contrast；用于检验第 14 节的概念独立性，不视为模型 A/B 实测。

### 15.1 三种操作的目标函数

#### Compare / Contrast

目标：

```text
A + B (+ C...)
→ explicit similarities / differences / ordering
```

主要产物：差异矩阵、相同点、冲突点、排序关系。

它不要求把多个对象形成一个新的整体模型。

#### Knowledge Structure Mapping

依据既有规范，其主要问题是：

> 当前领域有哪些 Node，以及它们之间到底是什么 Relation？

核心动作包括 Node Extraction、Node Typing、Relation Typing、Sibling / Axis 检查、Tree / DAG / Facet / Graph 决策、Unknown / Conflict 标记。

主要产物：**语义正确的结构模型 / Map**。

它优先优化 relation correctness 与 semantic fidelity；并不天然要求从多个局部结论形成一个新的高阶判断。

#### Synthesis

目标：

```text
Partial Results / Claims / Models
→ coordinate relations + constraints + evidence status
→ merge where justified / preserve separation where needed
→ Candidate Joint Model
```

主要产物：**可供后续推论、验证或决策的候选整体模型**。

因此 Synthesis 的目标不是“结构画对”，而是“多个局部结果共同意味着什么”。

### 15.2 相同材料的跨任务测试

#### Task A｜纯概念结构

材料：
- Advantage 是 Relative Effect 的一个 Value；
- Transformation 属于 Operation；
- Relationship 属于 Locus。

Compare：
- 能指出三者属于不同类型 / 维度。

Knowledge Structure Mapping：
- 能建立三个 Facet，并修正错误 sibling hierarchy；
- 这是本任务的充分操作。

Synthesis：
- 除非还要求回答“这些分面共同构成怎样的 Premise Architecture”，否则没有明显额外收益。

**判定**：在纯结构任务中，Synthesis 不是必需；不能把所有结构化都叫 Synthesis。

#### Task B｜相互冲突的研究证据

材料：
- Study A 支持 X；
- Study B 不支持 X；
- Study C 只在某人群支持 X；
- 三者测量、样本、时段不同。

Compare：
- 找到设计、样本和结果差异。

Knowledge Structure Mapping：
- 可把 Study / Population / Measure / Outcome / Condition 的关系组织成图；
- 可以标记 CONFLICT。

Synthesis：
- 进一步形成候选高阶模型，例如：
  “当前证据更支持 X 是条件性的，而不是普遍效应；人群/测量差异可能解释部分异质性；仍有冲突待验证。”
- 该结论必须区分 source fact 与 inference。

**判定**：这里 Synthesis 产生了结构图本身没有给出的 joint epistemic model，存在明显增量。

#### Task C｜当前 Operator Audit

材料：
- Clarification 较接近 L0；
- Scope Refinement 被 Clarification 吸收；
- Concept Explication 属于 L1；
- Deduction / Induction / Abduction 属于 Method Layer；
- Revision / Update 属于 State Update；
- Externalization 属于独立 Operator 候选。

Compare：
- 能比较各项属性。

Knowledge Structure Mapping：
- 能整理为 L0 / L1 / Method / Action / State Update 等层级和关系。

Synthesis：
- 进一步形成解释：
  “旧列表的问题不是只有冗余，而是混合了 transformation、inference method、acquisition action、state update 与 interface；因此 Operator Library 必须与运行架构分层。”
- 该高阶判断会反过来改变后续整个审计方法。

**判定**：Synthesis 对“多个局部审计共同意味着什么”有独立控制价值。

#### Task D｜互斥假设尚未获得区分证据

材料：H1、H2、H3 均能解释当前数据。

此时：
- Compare / Implication / Discrimination / Evidence Seeking 优先；
- 强行 Synthesis 成一个统一解释可能制造 false coherence。

**判定**：Synthesis 有明确“不应调用”的条件，进一步支持其是一个有边界的控制单元，而不是“凡是复杂就综合”。

### 15.3 消融结论

若删除 Synthesis：

```text
Compare
+ Knowledge Structure Mapping
+ Validation
+ Alternative Generation
```

可以复制大量局部步骤，但仍缺少一个稳定控制目标：

> **“基于多个局部结果，构造它们共同支持的候选整体模型，并明确哪些内容被合并、条件化、保留冲突或仍待验证。”**

因此：

- **严格原子独立性**：不成立；
- **功能独立性**：成立；
- **Human–AI Control Utility**：较高；
- **当前层级**：L1 Composite Operator / Protocol。

### 15.4 Synthesis 的触发条件

优先调用 Synthesis，当：

1. 已存在两个以上有实质内容的局部 Representation / Result；
2. 这些结果之间存在互补、重叠、约束或冲突；
3. 下游任务需要一个 joint model，而不仅是差异列表；
4. 当前材料足以形成候选整体，或至少足以明确哪些部分暂不可整合。

不优先调用，当：

- 目标只是比较 A/B；
- 目标只是建立 taxonomy / graph；
- 竞争假设应继续保持分离等待证据；
- 只是做摘要 / 压缩；
- 尚缺关键材料，任何统一模型都会主要来自猜测。

### 15.5 Synthesis 的停止条件

达到以下状态即可停止：

- 已形成支持当前下游任务的 Candidate Joint Model；
- 被合并与被保留分离的部分均有理由；
- unresolved conflicts / uncertainty / provenance 被明确保存；
- 继续综合不会在没有新证据的情况下实质改变模型。

```text

↓
Relations & Constraints
↓
Merge / Keep Separate / Conflict
↓
Candidate Joint Model
↓

↓
Unresolved Conflicts / Validation Needs
```
