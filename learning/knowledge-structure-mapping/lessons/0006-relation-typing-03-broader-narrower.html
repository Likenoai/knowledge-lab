Knowledge Structure Mapping · Relation Typing 03

BROADER / NARROWER（更广 / 更窄）

当两个概念明显存在语义上的广狭关系，但还不准备做严格的 IS_A / SUBCLASS_OF 声明时，可以使用 BROADER / NARROWER。

1. 为什么还需要 BROADER / NARROWER？

IS_A 是较强的本体声明：

A IS_A B ≈ “任何 A，在定义上都应该属于 B。”

如果我们只确定“B 比 A 更广”，但还没有足够依据证明严格 subclass，则可先用更保守的 BROADER / NARROWER。

2. 方向

较窄概念 → NARROWER_THAN → 较广概念 较广概念 → BROADER_THAN → 较窄概念

在项目词表里，我们主要用 BROADER / NARROWER 表示概念广狭；实际画图时必须保持方向一致，不要只写一个无方向的“broader”。

3. 与 IS_A 的差别

IS_A： 严格子类关系 BROADER / NARROWER： 概念层面的广狭关系， 但不一定承诺严格 subclass
