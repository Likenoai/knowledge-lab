Knowledge Structure Mapping · Relation Typing 04

关联、顺序、机制与等价

这一课继续扩展 Relation Typing。目标不是背名字，而是建立“看到一条边，就先判断它属于哪一类语义”的结构意识。

1. BROADER / NARROWER（更广 / 更窄）

用于概念广狭关系，尤其当我们只想表达“一个概念比另一个更一般 / 更具体”，但不准备做严格的 subclass（子类）声明时。

较窄概念 → NARROWER → 较广概念 较广概念 → BROADER → 较窄概念

它比 IS_A 更保守。IS_A 是“定义上是一种”；BROADER / NARROWER 只先承诺概念范围的广狭。

2. ASSOCIATED_WITH（关联）

当两个概念稳定相关，但不存在可靠的上下位、部分整体、取值维度、时间先后或机制关系时，用 ASSOCIATED_WITH。

Suspense ↔ ASSOCIATED_WITH ↔ Curiosity

关键点：“关系强”不等于“有层级”。

3. PRECEDES（先于）

PRECEDES 只表达 temporal / procedural order（时间 / 流程顺序）。

Premise Analysis → PRECEDES → Plot Analysis

A 在 B 前面，不代表 A 是 B 的父节点、组成部分或原因。

4. CAUSES / ENABLES / CONSTRAINS（导致 / 使能 / 约束）

CAUSES（导致）

A 的变化会产生 B，强调因果生成。

A → CAUSES → B

ENABLES（使能）

A 让 B 成为可能，但 A 本身未必足以保证 B 发生。

Information Asymmetry → ENABLES → Dramatic Irony

CONSTRAINS（约束）

A 限制 B 的可选范围、行为方式或状态空间。

Budget → CONSTRAINS → Production Choices

5. EQUIVALENT_TO / SAME_AS（等价 / 同一）

这是非常强的关系，只有在两个节点真正等价或指向同一对象时才使用。

以下情况都不足以推出 EQUIVALENT_TO：

  • 高度相似
  • 当前外延恰好相同
  • 经常一起出现
  • 在某个案例里暂时可互换
Similarity ≠ Equivalence Association ≠ Equivalence Same current extension ≠ Same concept

6. 把关系按“语义家族”整理

Relation Family（关系家族）核心关系回答的问题
Instantiation（实例化）INSTANCE_OF这个具体对象属于哪一类？
Taxonomic / Hierarchical（分类 / 层级）IS_A, BROADER / NARROWER哪一个概念更一般 / 更具体？
Mereological（部分—整体）PART_OF谁是谁的组成部分？
Faceted（分面）VALUE_OF, FACET_OF哪个是取值、哪个是维度、维度描述哪个模型？
Associative（关联）ASSOCIATED_WITH两个概念是否相关，但不构成其他更强关系？
Temporal / Procedural（时间 / 流程）PRECEDES谁先发生？
Mechanistic（机制）CAUSES, ENABLES, CONSTRAINSA 如何影响 B？
Equivalence（等价）EQUIVALENT_TO / SAME_AS两个节点是否真正等价 / 同一？

7. Structure Mapping 的关键升级

以前的问题是：

看到三个相关概念 → 先想谁是父节点、谁是子节点

现在应该变成：

看到两个节点 → 先判断 Node Type → 再判断 Relation Type → 最后才决定结构表示

主要是单一层级关系 → Tree / DAG 多个独立描述轴 → Faceted Model is-a + part-of + causal + temporal + association 混合 → Labeled Graph
