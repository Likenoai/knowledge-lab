# 原则知识对象与引用约定（v0.1）

## 职责和已有规范的关系
与 [知识沉淀协议](../../KNOWLEDGE_CAPTURE_POLICY.md) 和 [人生原则注册表](../../principles/人生原则注册表.md) 兼容；不更改原有 P 系列含义及成熟度模型。

| kind | 存储区 | 保存内容 | 不保存内容 |
|---|---|---|---|
| principle | `principles/` | ID、名称、状态、可调用的精简表达及来源 | 长篇推导 |
| concept | `concepts/` | 定义、语义边界与区分 | 规范结论的证明 |
| argument | `research/<topic>/` | 命题、前提、理由、证据、反驳、问题 | 假装已验证的结论 |
| metaphor | `metaphors/` | 隐喻正文、映射、适用范围及失效边界 | 独立证明 |

## ID 约定
- 原则延续现有 `P-001` 格式；不得回收历史 ID。
- 新概念 `C-<主题>-NNN`；研究论证 `A-<主题>-NNN`；隐喻 `M-<主题>-NNN`。
- ID 是稳定引用；文件名、标题可以变更，但须同步更新所有反向链接。
- Markdown 的相对链接是直接可点击的文档导航；YAML 的 `related_*` 字段用于将来 Agent/MCP 结构化读取。
- 关联只是引用，不意味着已经证实某条推导关系。

## 状态纪律
原则状态沿用注册表的 Candidate / Working Principle / Supported Principle / Canonical Principle 等现有类别。概念、论证和隐喻可分别使用 working-definition、open、working，不与原则成熟度混同。

## 维护流程
1. 改动概念或论证后，检查依赖它的原则措辞、状态和调用边界。
2. 改动隐喻后，不得未经论证就将它视为证据。
3. 同一对象优先修订原文件；保留修改原因，避免平行冲突版本。
4. Git 提交后重新读取新增与变更文件，并检查相对路径。
