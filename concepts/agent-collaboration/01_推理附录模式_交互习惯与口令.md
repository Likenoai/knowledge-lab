# 推理附录模式：交互习惯与开关口令

> 状态：Working Interaction Protocol（工作交互协议）v0.2
>
> 术语治理：遵循 `03_OpenAI_Reasoning术语治理_官方术语优先.md`。
>
> 目的：把 Reasoning Summary（推理摘要）与 Reasoning Reconstruction（推理重构）从一次性输出偏好，提升为可持续、可切换、可记录状态的长期交互习惯。

## 1. 概念引出

用户希望理解 Agent 的判断形成过程，但又不能、也不应把 raw chain of thought（原始思维链）或 Reasoning State（推理状态）直接暴露。

因此需要一个位于 Answer（回答）之外、但随回答一起出现的可共享解释层。

候选名称：

- Reasoning Transparency Mode（推理透明模式）：过强，容易误解为隐藏推理被直接公开；
- Reasoning Visibility Mode（推理可见模式）：仍可能误导为“内部推理可见”；
- Reasoning Annotation Mode（推理附注模式）：准确，但弱化了它作为固定交互层的意义；
- Reasoning Appendix Mode（推理附录模式）：最符合实际——它是在正文之后附加的、独立展示的推理解释层。

当前采用：

# **Reasoning Appendix Mode（推理附录模式）**

## 2. Reasoning Appendix（推理附录）的定义

Reasoning Appendix 是跟随 Answer 出现的独立解释层，由两个部分组成：

### A. Reasoning Summary（推理摘要）

- 如果系统实际提供正式、可共享的 Reasoning Summary，则原样展示；
- 只有当前系统 / API 实际提供官方 Reasoning Summary 时才展示该区块；
- 如果当前接口没有提供 Reasoning Summary，则不自行生成同名摘要；
- 不得把它描述成 Reasoning State 的直接解码；
- 不得把它描述成 raw chain of thought 的节选。

### B. Reasoning Reconstruction（推理重构）

用于重构从问题到结论的关键路径：

```text
问题
↓
关键变量
↓
候选判断 / 解释
↓
比较、排除或修正
↓
证据与边界
↓
当前结论
```

它是解释性重构，不是隐藏思维的逐字回放。

## 3. 开关口令

Canonical Commands（规范口令）：

```text
推理附录：开
```

作用：
- 将 Reasoning Appendix Mode 设置为 ON；
- 后续具有实质推理内容的回答，在正文后默认附带：
  1. Reasoning Summary（若系统实际提供）
  2. Reasoning Reconstruction
- 两部分以独立代码块、独立 Markdown 区块或独立文档展示，不与正文平铺混排。

```text
推理附录：关
```

作用：
- 将模式设置为 OFF；
- 后续默认只输出正常 Answer；
- 若用户某一轮明确请求 Summary 或 Reconstruction，仍可单次输出，不改变长期模式。

可选查询口令：

```text
推理附录：状态
```

作用：
- 返回当前 ON / OFF 状态以及当前展示规则；
- 不修改状态。

## 4. 状态持久化

当前模式状态不只存在于聊天上下文，而应写入 Knowledge Lab 的：

`/INTERACTION_STATE.md`

每次用户使用“推理附录：开 / 关”时：

1. 立即采用新状态；
2. 同步更新 `INTERACTION_STATE.md`；
3. Git commit 使用中文；
4. 后续可通过读取该文件恢复协作状态。

## 5. ON 状态下的默认展示

正文结束后，如系统实际提供 Reasoning Summary：

```text
Reasoning Summary
...
```

随后或在无官方 Summary 时直接展示：

```text
Reasoning Reconstruction
...
```

若系统确实提供正式 Reasoning Summary，则第一块标题改为：

```text
Reasoning Summary
...
```

## 6. 适用范围

ON 不等于每一句简单回复都强行制造复杂推理。

默认规则：

- 研究、分析、概念建构、决策、比较、诊断、设计：完整附加；
- 简单事实、确认、文件链接、工具执行结果：可以极短附加，或在没有实质推理时省略；
- 涉及隐藏推理边界时，不因模式开启而暴露 raw chain of thought 或 Reasoning State。

## 7. 与现有概念的关系

```text
raw chain of thought
→ 隐藏过程

Reasoning State
→ 隐藏内部状态

Answer
→ 正文

Reasoning Appendix Mode = ON
→ 在 Answer 之后附加：
   ├─ Reasoning Summary / Reasoning Summary
   └─ Reasoning Reconstruction
```

## 8. 设计原则

该模式追求的不是“把模型脑内所有东西倒出来”，而是：

> **Cognitive Inspectability（认知可检查性）**

即让用户能够检查：
- 结论依赖哪些关键判断；
- 哪些变量被考虑；
- 哪些候选路径被排除；
- 哪个边界变化会改变结论。

这比追求不可访问的原始隐藏推理更适合长期人—Agent协作。
